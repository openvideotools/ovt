## 17.3 Assumptions

- Reference hardware for performance budgets: Apple M1 MacBook Air (8 GB, `m1-air-8gb`), an x86_64 Linux desktop with a Mesa-supported GPU (`linux-x64-ref`), a Google Pixel Tablet (SDR panel, `pixel-tablet`), an HDR-capable Android tablet (`android-hdr`, Q14) and an HDR-capable Chromebook (`chromebook-hdr`) — chapter 14 §14.9.2; budgets in chapter 0 §0.7.4 and `tests/perf/budgets.json`.
- Conformance corpora remain downloadable from ITU, JCT-VC, AOM and MPEG locations listed in chapter 14; the corpus fetcher caches them.
- libvmaf ≥ 3.0.0 (models `vmaf_v0.6.1`, `vmaf_v0.6.1neg`, `vmaf_4k_v0.6.1`), FFmpeg ≥ 7.1 (xpsnr filter, current side-data API), libaom ≥ 3.9 (oracle 3.12.1), libde265 1.0.15, libplacebo ≥ 7, HM-18.0, Qt 6.8.3 LTS, NDK r27c (minSdk 28, targetSdk 36), CMake ≥ 3.25, Clang ≥ 16 / GCC ≥ 13, Python ≥ 3.11 are the pinned baselines at the time of writing (D5); `third_party/VERSIONS.md` is the source of truth once the repository exists.
- The implementation team can run macOS and Linux CI and has access to at least one Android tablet and one HDR-capable Chromebook for manual HDR checks.
