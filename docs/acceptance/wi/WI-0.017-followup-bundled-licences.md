# WI-0.017 follow-up: licence texts of code bundled inside libvmaf and libplacebo

Date: 2026-11-07. Machine: Linux cloud container. Karl's decision of 2026-11-07: binary distribution needs full
GPLv3 compliance, including every licence text (WI-0.036).

## Method

`code.videolan.org` is blocked in the container, so libplacebo was read from the `v7.349.0` tag of the GitHub mirror
`haasn/libplacebo`, libvmaf from the `v3.0.0` tag of `Netflix/vmaf` (commit `17a67b2`). The GitLab archive pinned in
`third_party/VERSIONS.md` has no submodules, so `src/` of the tag is what is compiled; **the pinned archive itself was
not opened here.** The owed check, on the Mini or hosted CI: `tar tjf libplacebo-v7.349.0.tar.bz2 | grep -c 3rdparty/.*/`
is 0 and `diff -r` of `src/` against the tag is empty.

Compiled code was found from `src/meson.build` of each project and from the copyright and licence headers of those
files. Texts are copied from the header of the bundled file; where the archive holds no text (mkdirp, pdjson, glumpy)
from the upstream project's own licence file.

The VMAF models are Netflix's (BSD-2-Clause-Patent, covered by the top-level LICENSE).

## libplacebo 7.349.0 (staged now, `third_party/licenses/libplacebo/`)

| Component | Files | Licence |
|---|---|---|
| SipHash | `src/hash.h` | CC0-1.0 |
| ccSeqParseDouble (Alexis Naveros) | `src/convert.cc` | Zlib (zlib-style text) |
| Glumpy filter code | `src/filters.c` (derived, via mpv) | BSD-3-Clause (text from glumpy `LICENSE.txt`; the source says only "new BSD") |

Not in the archive and so not staged here: fast_float (vcpkg port, `share/fast-float/copyright`), lcms2, glslang,
Vulkan headers (vcpkg ports; read by `gen_notices.py --vcpkg-share`), jinja and markupsafe (build-time Python only),
glad (Android only, generated by the `glad2` pip package at build time). Code taken from mpv and from FFmpeg's
yadif CUDA filter (`shaders/dithering.c`, `deinterlacing.c`) is LGPL-2.1-or-later like libplacebo.

## Other vendored dependencies (findings, no change in this PR)

- **libaom 3.12.1** (script pending in #154): `third_party/` holds libwebm (BSD-3-Clause + `PATENTS.TXT`), libyuv
  (BSD-3-Clause), x86inc (ISC), fastfeat (BSD-3-Clause, Edward Rosten), vector (MIT), SVT-AV1 (`LICENSE.md`:
  **BSD-3-Clause-Clear**, with `PATENTS.md`) and googletest (tests only). `LICENSE_FILES` for libaom should list
  `LICENSE`, `PATENTS` and the `third_party/*/LICENSE*` files. BSD-3-Clause-Clear is not an id in
  `tools/license_policy.toml`, and its code **is compiled in by default**: `CONFIG_SVT_AV1=1` adds the SVT-AV1 AVX2
  convolution headers to `aom_dsp` on x86. It is permissive but says explicitly that no patent licence is granted
  (the AOM PATENTS grant covers libaom's own code). A new licence id is a Karl decision (project rules), so #154 or a
  follow-up should raise it, or build with `-DCONFIG_SVT_AV1=0` (decoder performance cost only).
- **dav1d 1.5.1**: `COPYING` is BSD-2-Clause only, but `src/ext/x86/x86inc.asm` is ISC (x264), `src/loongarch/
  loongson_asm.S` is ISC and `src/arm/64/mc16_sve.S` is BSD-2-Clause (Arm). `dav1d.cmake` staged `COPYING` only. **Fixed in this PR**: both ISC texts are staged
  (`third_party/licenses/dav1d/`; the Loongson file is read from the GitHub mirror tag 1.5.1, not the pinned tarball).
- **libde265 1.0.15**: `libde265/md5.cc` is public domain (Alexander Peslyak) with a fallback permissive grant, and
  `libde265/arm/*` is LGPL-2.1-or-later (from FFmpeg). Both are compatible with LGPL-3.0-or-later; the md5 grant was
  not in `COPYING`. **Fixed in this PR**: staged as `LicenseRef-Peslyak-md5-public-domain` (also in `LICENSES/`; a new
  LicenseRef id for the REUSE check only, not a policy entry).
- **FFmpeg n7.1.1**: `LICENSE.md` is staged and lists the bundled components. No gap found.
- **HM, MoltenVK, ONNX Runtime**: not examined (MoltenVK and ONNX Runtime stage their own notice files).

No licence incompatibility was found: every bundled text is permissive (BSD, MIT, ISC, Zlib, CC0, Unlicense) or LGPL.
